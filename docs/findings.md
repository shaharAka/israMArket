# Findings and review actions

Recommendations are proposals, not applied changes. `recommendation_context` binds each generation to the active plan and a dated source snapshot. Both `/recommendations/generate` and `/performance/weekly` use the same contract. It keeps GA4, Meta ads and social windows separate, including older Meta retained by a GA-only read and Instagram-only reach. Selected site/account mismatches are excluded from the model input, including their combined diagnostic. Undated per-post results, learning and the old hypothesis review are omitted from the model's plan context; the owner can still read them in the existing plan/editor. Finite, nonnegative raw counts provide the displayed observations; missing values never become zero. Model-written hypotheses, reasoning and experiments stay distinct from those counts.

`GET /recommendations/{id}` is scoped to the signed-in business. A post destination uses an exact unique UID from the serialized plan, including the normal backfill for old posts. Reads resolve its current position, detect changed copy and reject replaced plans, removed posts and ambiguous IDs. Published posts return to plan review for the next post. The server supplies only fixed app paths. Legacy recommendations keep their text but cannot claim source provenance or guess a post destination.

`FindingCard` leads with one proposal; additional proposals and source details are disclosed on demand. The same component appears in Results, Recommendations and the clearly fictional `/design/results` rehearsal. Results puts detailed reports behind source disclosures while keeping failed reads visible. A recommendation bound to the displayed snapshot remains usable even if the separate diagnostic has not completed; an older recommendation is hidden while that snapshot's analysis is pending. The URL carries the recommendation ID to read-only review context in the existing plan or editor. The Posts page checks the plan, UID and publication state again, and skips batch image generation throughout a recommendation visit, including return to the feed. Opening a review does not rewrite, approve, publish or mark an experiment successful. The previous local-only “adopt” and false “saved” controls are removed. Plan and website review do not imply that full plan editing or external website updates are implemented.

A read is marked older when its date or source window is more than seven days old, or its date is unknown. Connection revocation or a changed selection also makes it historical. This is a visible caution, not an automatic claim that the underlying numbers are incorrect. Important events and ad clicks are not verified enquiries or orders; provider-attributed purchases are never added together.

Hermetic tests cover source periods, missing/zero/invalid counts, selection changes, model-controlled fields, stable review IDs, customer isolation, reordered/edited/removed/published posts, legacy records, both generation paths and provider failure. Demo and rehearsal checks do not establish live multi-provider analysis quality. The latter, Claude’s design pass and owner comprehension review remain acceptance work on #46. Reading a recommendation does not make a paid model call.
